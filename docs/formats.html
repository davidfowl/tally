#settings.yaml

The main configuration file. Created by tally init.

title: "2025 Budget"

currency_format: "${amount}"  # Optional: defaults to $

merchants_file: config/merchants.rules
views_file: config/views.rules    # Optional: custom report sections

data_sources:
  - name: Chase
    file: data/chase.csv
    format: "{date:%m/%d/%Y},{description},{amount}"

  - name: Bank of America
    file: data/bofa.csv
    format: "{date:%m/%d/%Y},{description},{amount}"

#Data Sources

Each data source represents a CSV file from a bank or credit card.

Field Required Description
name Yes Display name (e.g., "Chase", "AMEX Gold")
file Yes Path to CSV file (relative or absolute), supports glob patterns (*, ?, []) to match multiple files (files are processed in sorted order)
format Yes Format string describing CSV columns
decimal_separator No For European format: "," (1.234,56)
columns No Custom column mappings (see Format Strings)
delimiter No Column delimiter: ; or other single char, tab, or regex:pattern
has_header No Set to false if file has no header row

Non-CSV Files

For tab-separated, whitespace-delimited, or fixed-width formats, use the delimiter option:

# Tab-separated file
- name: Bank Statement
  file: data/stmt.tsv
  delimiter: tab
  format: "{date:%m/%d/%Y},{description},{amount}"

# Fixed-width with regex capture groups
- name: BOA Statement
  file: data/stmt.txt
  delimiter: "regex:^(\\d{2}/\\d{2}/\\d{4})\\s+(.+?)\\s+([-\\d,]+\\.\\d{2})\\s+([\\d,]+\\.\\d{2})$"
  format: "{date:%m/%d/%Y},{description},{-amount},{_}"
  has_header: false

Regex delimiters use capture groups () to extract columns. Each group becomes a column matched by the format string.

#Format Strings

Format strings describe how to parse each CSV column. They map your CSV structure to the fields Tally needs.

Basic Tokens

Token Description
{date:%m/%d/%Y} Date with format specifier
{description} Transaction description
{amount} Amount column (keep sign as-is)
{-amount} Amount column (negate the value)
{+amount} Amount column (take absolute value)
{_} or {*} Skip this column
{custom_name} Capture column as custom field

Amount Signs

Different banks format amounts differently. Use the right token:

# Charges are positive, payments are negative (most credit cards)
format: "{date},{description},{amount}"

# Charges are negative, deposits are positive (most bank accounts)
# Use {-amount} to flip the sign so spending is positive
format: "{date},{description},{-amount}"

# All amounts are positive, separate debit/credit columns
# Use {+amount} to ensure positive, skip the other column
format: "{date},{description},{+amount},{_}"

Capturing Custom Fields

Any token besides the reserved ones becomes a custom field you can use in rules:

# CSV: Date, Type, Memo, Vendor, Amount
format: "{date:%m/%d/%Y},{txn_type},{memo},{vendor},{amount}"

# Now use in merchants.rules:
# match: field.txn_type == "WIRE"
# match: contains(field.memo, "Invoice")

A captured column is available to rule expressions, but is not shown in the report until you ask for it. The simplest way is report_fields, which surfaces the column as-is:

report_fields:
  - memo

Transactions with a blank value show no details badge. A rule's field: directive also shows up in the popup, and is what you want when the value needs computing rather than copying. See the rules reference for per-source overrides and how the two interact.

Combining Columns into Description

Some CSVs split transaction info across multiple columns. Use columns.description to combine them:

# CSV: Date, Category, Payee, Reference, Amount
- name: My Bank
  file: data/bank.csv
  format: "{date:%m/%d/%Y},{category},{payee},{ref},{amount}"
  columns:
    description: "{payee} - {category}"
# Result: "AMAZON - Shopping" instead of just one column

The template can reference any captured field:

# Include reference number for matching
columns:
  description: "{payee} ({ref})"
# Result: "AMAZON (INV-12345)"

Examples

# Simple: date, description, amount
format: "{date:%m/%d/%Y},{description},{amount}"

# Skip columns you don't need
format: "{date:%m/%d/%Y},{_},{description},{_},{amount}"

# Bank account with negated amounts
format: "{date:%m/%d/%Y},{description},{-amount}"

# European bank with custom description
- name: German Bank
  file: data/german.csv
  format: "{date:%d.%m.%Y},{_},{txn_type},{vendor},{_},{amount}"
  decimal_separator: ","
  columns:
    description: "{vendor} ({txn_type})"

#Date Formats

Common date format specifiers:

Format Example Notes
%m/%d/%Y 01/15/2025 US format
%d/%m/%Y 15/01/2025 European format
%Y-%m-%d 2025-01-15 ISO format
%d.%m.%Y 15.01.2025 German format
%m-%d-%Y 01-15-2025 US with dashes

#Currency Format

Display amounts in your local currency:

# US Dollars (default)
currency_format: "${amount}"      # → $1,234.56

# Euro
currency_format: "€{amount}"      # → €1,234.56

# British Pound
currency_format: "£{amount}"      # → £1,234.56

# Polish Zloty (suffix)
currency_format: "{amount} zł"   # → 1,234.56 zł

# Japanese Yen (no decimals)
currency_format: "¥{amount}"      # → ¥1,234

European Number Format

For CSVs using comma as decimal separator:

- name: German Bank
  file: data/german.csv
  format: "{date:%d.%m.%Y},{description},{amount}"
  decimal_separator: ","  # Parses 1.234,56 correctly

#Travel Tracking

To track travel expenses, use a Travel category in your merchant rules:

# In merchants.rules:
AIRBNB -> "Airbnb", Travel, Lodging
SOUTHWEST -> "Southwest", Travel, Flights
UBER -> "Uber", Travel, Transport

#Categorization Review Files

An alternate way to answer unknown merchants, in an editor instead of chat — see the Guide for the walkthrough and worked example. This section is the field-by-field reference.

When merchants_file is set and unknown merchants remain after tally up, three files are written to the config directory:

File You edit it? Purpose
categorization.yaml Yes One row per uncategorized transaction. Fill in useRule, newRule, or edits, then tell your agent to process it.
categorization.hints.yaml No Deterministic match data, correlated by key/id. Computed with Python's difflib against your own merchants.rules — no AI, no network. Regenerated every run; safe to delete.
categorization-schema.json No JSON Schema that drives editor autocomplete (Ctrl+Space) and hover text on categorization.yaml.

categorization.yaml fields

Field Owner Description
id Machine Display label only, for referring to a row in chat (e.g. "process 7, 9, 13"). Renumbered from 1 on every run — not stable.
key Machine Stable identity for this row across runs. Do not edit — changing it orphans whatever you filled in.
source, date, merchant, amount Machine Display-only copy of the transaction, exactly as parsed from the source CSV. Rewritten every run; edits are discarded.
aiNotes Agent Blank until you ask your agent to "annotate" a row. Tally never writes or overwrites this field, and preserves it verbatim while the row is unresolved. A blank value means the agent hasn't written anything here — not that you owe an answer.
useRule You Label of an existing rule to widen so it also covers this transaction, e.g. "[Theory11] Shopping / Christmas". Ctrl+Space autocompletes from every rule currently defined.
newRule You Free-form prose describing a brand-new rule, e.g. "new rule: Category Shopping / Books, tag gift". Tally does not parse or validate this at all — your agent reads it back and creates the rule.
edits.category / edits.tags / edits.memo You One-off overrides for just this transaction, for when no existing or new rule is worth creating.

reviews: fields

Rows appear here only when a rule in merchants.rules carries review: true (see the Guide) and its source file isn't marked reviewComplete: true in inventory.yaml (below). Unlike unknown rows, review rows don't drop out when regenerated — they persist indefinitely, across months and files, until the file is marked complete. Leave a row untouched and the rule that matched it keeps applying. Ids continue the same sequence as the unknowns list above, so a row number is never ambiguous.

Field Owner Description
id, key, source, date, merchant, amount Machine Same as the unknowns table above — the id sequence continues rather than restarting.
currently Machine How this transaction is categorized right now, by the rule that matched it. This is what stands if you leave the row alone.
file Machine Data file this transaction came from. Set this path's reviewComplete to true in inventory.yaml to stop its rows appearing here.
aiNotes, useRule, newRule, edits.* Agent / You Same as the unknowns table above.

categorization.hints.yaml fields

Everything here comes from comparing the transaction's raw description against your own merchants.rules with difflib — literal character similarity, not an AI opinion.

Field Meaning
nearest[].merchant A merchant already in merchants.rules.
nearest[].score Character similarity, 0-1. 1.0 means the merchant name appears verbatim in the transaction text — not a confidence score.
nearest[].rules How many rule variants that merchant has. Greater than 1 means the category depends on what was bought, so there's no single answer to hand you.
nearest[].useRule Present only when rules == 1 — an unambiguous answer, ready to paste into that row's useRule in categorization.yaml.
occurrences How many unresolved transactions share this exact description.
priorPeriod The rule label this exact description matched in an earlier period, if any.
amountSpread Min-max amount across those occurrences, shown when they differ.
refund true when the amount is a credit rather than a charge.

Regeneration and merging

Every tally up re-merges the file: rows whose transaction now matches a rule are dropped, and rows still unknown keep whatever you filled in (useRule, newRule, edits, aiNotes) even though id gets renumbered. Your previous answer is matched to the right row by the stable key field, never by id.

Malformed YAML

If categorization.yaml doesn't parse, tally up still writes the HTML report — the categorization step fails on its own, with a message pointing at the line and column, and the file is left completely untouched. Fix the syntax error and re-run; nothing is lost. The most common cause is an unquoted value containing a : — wrap it in quotes, e.g. newRule: "Amazon: books only".

Disabling it

# In settings.yaml:
generate_categorization_file: false

Set to false to stop tally from writing these files at all. Categorizing by talking to your agent in prose still works exactly the same either way. The setting is named generate_categorization_file rather than the shorter categorization for two reasons: the old name read as "stop categorizing my transactions" — tally's entire purpose — and the _file suffix matches merchants_file / views_file, with the generate_ prefix making clear this is a boolean toggle, not a path.

Turning generation off never deletes files already on disk — categorization.yaml may hold answers you typed, and a config toggle must not destroy that. Instead, if a categorization.yaml is still present, tally up prints a warning that it is stale and leaves it alone:

Categorization: generation is off (generate_categorization_file: false)
  config/categorization.yaml is STALE — written 2026-08-01T10:34:27, not updated since.
  Ignore its contents, or delete it. Re-enable to refresh.

The warning only appears when a file is actually present, and it never fails the run — even a malformed or unreadable categorization.yaml just yields a notice without a date. Delete the file yourself if you want it gone. config/inventory.yaml keeps registering data files while generation is off, so registered still records when tally first saw each file. Anything registered in the meantime carries reviewComplete: false and surfaces for review once you re-enable.

#Data File Inventory

config/inventory.yaml is tally's own register of every data file it has parsed, and whether you've confirmed the categorizations in it. See the Guide for the walkthrough; this section is the field reference.

Field Description
path Data file path, relative to the budget directory when possible (absolute otherwise). This is the match key tally uses to find this entry again on the next run.
source Name of the data source (as configured in settings.yaml) this file was parsed as.
registered Date tally first saw this file.
reviewComplete Boolean, written false for every new entry. Set to true to confirm the file and stop its review: true rows from appearing in categorization.yaml; set it back to false to force them back into review — e.g. after appending new rows to an existing CSV.

This is the whole schema — any other key is rejected outright (a typo like reviewComplte would otherwise silently lose the flag). Tally auto-registers every file it parses and only ever appends: it never modifies or removes an existing entry, so a hand-set reviewComplete always survives a run. A reviewComplete value that isn't true or false is a hard error.

reviewComplete is review-scoped only. It never gates parsing or analysis — every transaction always feeds the report's totals and monthly averages, and tally discover always sees everything regardless of any file's review state.

There is no tally command that sets reviewComplete — you or your agent edit it directly in the file. Malformed YAML hard-fails the same way as categorization.yaml: the report is still written, the error names the line and column, and the file is left untouched. PyYAML doesn't preserve comments, so anything you add to this file is lost the next time tally rewrites it (ruamel.yaml, which would preserve them, is deliberately not a dependency).

#CLI Commands

Command Description
tally init [dir] Create a new budget folder
tally workflow Show next steps (context-aware)
tally up Generate HTML spending report
tally inspect <csv> Analyze CSV structure and detect column types
tally discover Find uncategorized transactions
tally explain <merchant> Explain merchant classification
tally diag Debug configuration issues
tally reference Show full reference docs

Output Formats

# Different output formats
tally up                       # HTML report (default)
tally up --format json         # JSON with reasoning
tally up --format csv          # CSV transactions (for Excel/Sheets)
tally up --format markdown     # Markdown report
tally up --format summary      # Text summary only

# Verbosity levels
tally up -v                    # Include decision trace
tally up -vv                   # Include thresholds, CV values

# Show changes since last run
tally up --diff                # Detailed diff output

Filtering

# Filter by classification
tally up --format json --only monthly,variable

# Filter by category
tally up --format json --category Food

# Explain specific classifications
tally explain --classification monthly
tally explain --category Subscriptions
tally explain --tags business

# Filter by month (name, number, or YYYY-MM)
tally explain --month Jan
tally explain --month 2025-01

# Combine multiple filters
tally explain --category Food --month Jan
tally explain --month 2025-01 --tags business
