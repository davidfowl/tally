Guide

Using Tally with AI assistants

#How It Works

Tally is a rule engine that classifies transactions. The AI assistant is the operator that writes the rules. Together they create a feedback loop:

  1. Tally finds uncategorized transactions
  2. AI identifies the merchants and writes categorization rules
  3. Tally applies rules and finds remaining unknowns
  4. Repeat until everything is categorized

#Supported AI Assistants

Claude Code Anthropic CLI
GitHub Copilot VS Code / CLI
Codex OpenAI CLI
Cursor AI IDE

Any AI agent that can run command-line tools will work with Tally.

#Starting a Session

After setting up your budget folder, open it in your AI assistant and tell it what to do:

"Use tally to configure my Chase credit card CSV"
"Use tally to categorize all my transactions"
"Use tally to generate my spending report"

The agent will run tally workflow to understand the current state and follow the instructions.

#The Workflow Command

The tally workflow command is context-aware. It detects your setup state and shows relevant next steps:

No data sources configured

tally workflow

No data sources configured yet.

To add a data source:
1. Run: tally inspect data/yourfile.csv
2. Add the suggested config to settings.yaml

Unknown merchants found

tally workflow

Found 47 unknown merchants.

Run: tally discover --format json
Then add rules to config/merchants.rules

Ready to generate report

tally workflow

All transactions categorized!

Run: tally up

#Key Commands for AI Agents

Discover unknown merchants

tally discover --format json

Returns uncategorized transactions with suggested patterns. The AI uses this to write rules.

Inspect CSV structure

tally inspect data/chase.csv

Analyzes CSV structure with column type detection (dates, currency, numbers, categorical). Shows samples for both positive and negative amounts to help understand sign conventions.

Explain a classification

tally explain Netflix -vv

Shows why a merchant is classified a certain way, including which rule matched. Supports combined filters:

tally explain --category Food --month Jan
tally explain --tags business --month 2025-01

Debug configuration

tally diag --format json

Validates configuration and shows any errors.

Run full analysis

tally up --format json -v

Returns complete analysis with classification reasoning.

#Writing Rules

When the AI finds unknown transactions, it adds rules to config/merchants.rules:

[Netflix]
match: contains("NETFLIX")
category: Subscriptions
subcategory: Streaming
tags: entertainment, recurring

[Whole Foods]
match: contains("WHOLEFDS") or contains("WHOLE FOODS")
category: Food
subcategory: Grocery

See the Reference for full syntax.

#Using Transforms

Transforms are top-level assignments in merchants.rules whose left side starts with field.. You can optionally include an @transforms line as a human-readable separator, but it isn't required by the parser.

Example: add a fee column to the transaction amount.

@transforms
# Strip $/commas from fee, then add to amount
field.amount = field.amount + regex_replace(regex_replace(field.fee, "\\$", ""), ",", "")

# Clean descriptions
field.description = regex_replace(field.description, "^APLPAY\\s+", "")
Tip: Be specific with the AI

Tell the AI your preferences: "Coffee shops should be Food > Coffee, not Food > Restaurant" or "Tag all Uber rides as business, reimbursable".

#Reviewing Unknowns in a File

Everything above works by talking to your agent in prose — "all VIOC is oil change", "these three are groceries" — and that's still the whole feature; nothing below changes it. If you'd rather answer at your own pace in an editor instead of a chat transcript that scrolls away, tally up gives you that option too. Both work, and you can mix them freely in the same session.

When unknown merchants remain after a run, three files land in your config directory:

  • categorization.yaml — one row per uncategorized transaction. This is the only file you edit.
  • categorization.hints.yaml — deterministic match data tally computed by comparing each transaction against your own merchants.rules. No AI, no network; safe to delete, regenerated every run.
  • categorization-schema.json — drives autocomplete and hover text while you edit categorization.yaml. You never open this one directly.

Fill in useRule, newRule, or edits for whichever rows you want to answer, save, then tell your agent to process the file.

A worked example

Suppose a run leaves 37 unknown transactions. Rows 1-28 are all Amazon orders, e.g. Amazon.com*SR9ZH2VE3. The hints file shows why tally didn't just guess:

  - id: 1
    key: "a6c27da1"
    merchant: "Amazon.com*SR9ZH2VE3"
    nearest:
      - merchant: "Amazon"
        score: 1.0
        rules: 25
    occurrences: 1

score: 1.0 means "Amazon" appears verbatim in the description — literal string containment, not an AI confidence value. rules: 25 is why there's no answer handed to you: this user's Amazon merchant already has 25 different category variants (books, electronics, gifts...), so which one applies depends on what was actually bought. A useRule is only ever suggested when a merchant has exactly one rule to offer.

Compare that to row 31, a one-off charge from Theory11:

  - id: 31
    key: "d6b0d02d"
    merchant: "THEORY11.COM CHARLESTON SC"
    nearest:
      - merchant: "Theory11"
        score: 1.0
        rules: 1
        useRule: "[Theory11] Shopping / Christmas"
    occurrences: 1
    refund: true

Theory11 has exactly one rule, so tally hands over the answer: paste [Theory11] Shopping / Christmas straight into that row's useRule: field in categorization.yaml and you're done. (refund: true just flags that this particular amount is a credit, not a charge.)

#Getting help on a row

additionalInfo stays blank until you ask for it — tally never writes or overwrites this field. Say "annotate" (or "annotate 5-12", or "annotate the Amazons") and your agent fills it in with its best guess and reasoning, then you answer from there. id is just a display label for talking about rows in chat ("process 7, 9, 13") — it's renumbered every run, so it always matches what's on screen right now.

Regenerating the file

Every tally up merges your previous answers back in: rows whose transaction now matches a rule drop out of the file entirely, and rows still unknown carry forward whatever you typed. Answers reattach by the stable key field, never by id.

See the Formats reference for the full field list, malformed-YAML behavior, and how to turn this off with categorization: false.

#Customizing Categories

Tally doesn't have predefined categories. You define them in your rules:

  • Category - Primary grouping (Food, Transportation, Bills)
  • Subcategory - Secondary grouping (Grocery, Rideshare, Utilities)
  • Tags - Labels for filtering (business, reimbursable, recurring)

Tell the AI your preferred structure and it will use it consistently.

#Generating Reports

Once transactions are categorized:

tally up

This generates an HTML report with:

  • Monthly spending breakdown
  • Recurring expense detection
  • Category summaries
  • Transaction search and filtering

#Iterating

As you review the report, you might want changes:

"Move Starbucks from Restaurant to Coffee"
"Split Amazon purchases - anything over $100 should be Shopping > Electronics"
"Tag all transactions in December as holiday"

The AI updates the rules, and you can regenerate the report.
