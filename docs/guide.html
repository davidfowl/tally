Guide

Using Tally with AI assistants

#How It Works

Tally is a rule engine that classifies transactions. The AI assistant is the operator that writes the rules. Together they create a feedback loop:

  1. Tally finds uncategorized transactions
  2. AI identifies the merchants and writes categorization rules
  3. Tally applies rules and finds remaining unknowns
  4. Repeat until everything is categorized

#Supported AI Assistants

Claude Code Anthropic CLI
GitHub Copilot VS Code / CLI
Codex OpenAI CLI
Cursor AI IDE

Any AI agent that can run command-line tools will work with Tally.

#Starting a Session

After setting up your budget folder, open it in your AI assistant and tell it what to do:

"Use tally to configure my Chase credit card CSV"
"Use tally to categorize all my transactions"
"Use tally to generate my spending report"

The agent will run tally workflow to understand the current state and follow the instructions.

#The Workflow Command

The tally workflow command is context-aware. It detects your setup state and shows relevant next steps:

No data sources configured

tally workflow

No data sources configured yet.

To add a data source:
1. Run: tally inspect data/yourfile.csv
2. Add the suggested config to settings.yaml

Unknown merchants found

tally workflow

Found 47 unknown merchants.

Run: tally discover --format json
Then add rules to config/merchants.rules

Ready to generate report

tally workflow

All transactions categorized!

Run: tally up

#Key Commands for AI Agents

Discover unknown merchants

tally discover --format json

Returns uncategorized transactions with suggested patterns. The AI uses this to write rules.

Inspect CSV structure

tally inspect data/chase.csv

Analyzes CSV structure with column type detection (dates, currency, numbers, categorical). Shows samples for both positive and negative amounts to help understand sign conventions.

Explain a classification

tally explain Netflix -vv

Shows why a merchant is classified a certain way, including which rule matched. Supports combined filters:

tally explain --category Food --month Jan
tally explain --tags business --month 2025-01

Debug configuration

tally diag --format json

Validates configuration and shows any errors.

Run full analysis

tally up --format json -v

Returns complete analysis with classification reasoning.

#Writing Rules

When the AI finds unknown transactions, it adds rules to config/merchants.rules:

[Netflix]
match: contains("NETFLIX")
category: Subscriptions
subcategory: Streaming
tags: entertainment, recurring

[Whole Foods]
match: contains("WHOLEFDS") or contains("WHOLE FOODS")
category: Food
subcategory: Grocery

See the Reference for full syntax.

#Using Transforms

Transforms are top-level assignments in merchants.rules whose left side starts with field.. You can optionally include an @transforms line as a human-readable separator, but it isn't required by the parser.

Example: add a fee column to the transaction amount.

@transforms
# Strip $/commas from fee, then add to amount
field.amount = field.amount + regex_replace(regex_replace(field.fee, "\\$", ""), ",", "")

# Clean descriptions
field.description = regex_replace(field.description, "^APLPAY\\s+", "")
Tip: Be specific with the AI

Tell the AI your preferences: "Coffee shops should be Food > Coffee, not Food > Restaurant" or "Tag all Uber rides as business, reimbursable".

#Reviewing Unknowns in a File

Everything above works by talking to your agent in prose — "all VIOC is oil change", "these three are groceries" — and that's still the whole feature; nothing below changes it. If you'd rather answer at your own pace in an editor instead of a chat transcript that scrolls away, tally up gives you that option too. Both work, and you can mix them freely in the same session.

When unknown merchants remain after a run, three files land in your config directory:

  • categorization.yaml — one row per uncategorized transaction. This is the only file you edit.
  • categorization.hints.yaml — deterministic match data tally computed by comparing each transaction against your own merchants.rules. No AI, no network; safe to delete, regenerated every run.
  • categorization-schema.json — drives autocomplete and hover text while you edit categorization.yaml. You never open this one directly. VS Code caches it, so after a run that added rules, Ctrl+Shift+P → "Developer: Reload Window" to pick up the new suggestions.

Fill in useRule, newRule, or edits for whichever rows you want to answer, save, then tell your agent to process the file.

A worked example

Suppose a run leaves 37 unknown transactions. Rows 1-28 are all Amazon orders, e.g. Amazon.com*SR9ZH2VE3. The hints file shows why tally didn't just guess:

  - id: 1
    key: "a6c27da1"
    merchant: "Amazon.com*SR9ZH2VE3"
    nearest:
      - merchant: "Amazon"
        score: 1.0
        rules: 25
    occurrences: 1

score: 1.0 means "Amazon" appears verbatim in the description — literal string containment, not an AI confidence value. rules: 25 is why there's no answer handed to you: this user's Amazon merchant already has 25 different category variants (books, electronics, gifts...), so which one applies depends on what was actually bought. A useRule is only ever suggested when a merchant has exactly one rule to offer.

Compare that to row 31, a one-off charge from Theory11:

  - id: 31
    key: "d6b0d02d"
    merchant: "THEORY11.COM CHARLESTON SC"
    nearest:
      - merchant: "Theory11"
        score: 1.0
        rules: 1
        useRule: "[Theory11] Shopping / Christmas"
    occurrences: 1
    refund: true

Theory11 has exactly one rule, so tally hands over the answer: paste [Theory11] Shopping / Christmas straight into that row's useRule: field in categorization.yaml and you're done. (refund: true just flags that this particular amount is a credit, not a charge.)

#Getting help on a row

aiNotes stays blank until you ask for it — tally never writes or overwrites this field. Say "annotate" (or "annotate 5-12", or "annotate the Amazons") and your agent fills it in with its best guess and reasoning, then you answer from there. id is just a display label for talking about rows in chat ("process 7, 9, 13") — it's renumbered every run, so it always matches what's on screen right now.

Regenerating the file

Every tally up merges your previous answers back in: rows whose transaction now matches a rule drop out of the file entirely, and rows still unknown carry forward whatever you typed. Answers reattach by the stable key field, never by id.

#Flagging a Rule for Review

Sometimes a rule is right most of the time but you still want a second look before it's final — a merchant that's occasionally a gift instead of a personal purchase, a category you're not fully sure of yet. Add review: true to that rule and every transaction it matches keeps surfacing for confirmation, even though it's already categorized.

review: true takes no conditions of its own — granularity belongs in the rule's own match:. Split out the specific case and flag only that rule:

[Theory11]
match: contains("THEORY11") and contains(field.tagging, "CATEGORY: Shopping / Christmas")
category: Shopping
subcategory: Christmas

[Theory11]
match: contains("THEORY11")
category: Shopping
subcategory: Christmas
review: true

The first rule only fires once a purchase has already been explicitly tagged as a Christmas gift — nothing to confirm there. The second, broader rule catches every other Theory11 charge, and those keep coming back for review until they're confirmed. Setting review: to anything other than true or false is a parse error that points you back at match: — that's the mechanism for narrowing what gets reviewed, not a condition on review: itself.

Compatibility warning

A merchants.rules file containing review: will not load on tally builds older than this release. The parser hard-fails on unknown properties — by design, and unchanged here — so it stops with Unknown property: review until the build is upgraded. If you share your rules file with someone else, or roll back your own install, keep this in mind.

#Confirming a Reviewed Transaction

Transactions matched by a review: true rule show up in a separate reviews: list in categorization.yaml, below the unknowns. Each row carries currently — how it's categorized right now, i.e. what stands if you do nothing — and file, the data file it came from. Leave the row alone and the rule that matched it keeps applying.

Row ids continue the same sequence as the unknowns above them, so "process 7, 9, 13" is never ambiguous about which list a number belongs to. Unlike unknown rows, review rows don't drop out of the file on their own — they persist indefinitely, across months and files, until the file named in file is marked reviewComplete: true in config/inventory.yaml (below). You answer a review row with the same fields as an unknown one: useRule to point at a different rule, newRule to describe a new one, or edits for a one-off override on just that transaction.

#The Data File Inventory

Alongside the categorization files, tally maintains config/inventory.yaml — a register of every data file it has parsed, and whether you've confirmed its categorizations:

# Data files tally has seen, and whether you have confirmed their
# categorizations. Tally only ever appends entries.
#
# Set reviewComplete: true to confirm a file and stop its rows
# appearing for review. Set it back to false to review a file again after
# appending new rows to the CSV.
#
# reviewComplete never affects parsing or analysis — every transaction is
# always included in your report totals.
#
# Note: comments you add below are lost when tally rewrites this file.

files:
  - path: "data/amazon-chase-visa-2026-Q2.CSV"
    source: "Amazon Chase Visa"
    registered: "2026-07-31"
    reviewComplete: true
  - path: "data/amazon-chase-visa-2026-Q3.CSV"
    source: "Amazon Chase Visa"
    registered: "2026-08-15"
    reviewComplete: false

Tally registers a file the first time it parses it and only ever appends — it never modifies or removes an existing entry, so a hand-set reviewComplete always survives a run.

Marking a file reviewed is entirely manual: set reviewComplete to true yourself, or ask your agent to do it for you, once you're satisfied with a file's categorizations. There's no tally command for it. Set it back to false to force that file's rows back into review — the documented recovery after appending new rows to an existing CSV.

reviewComplete is review-scoped only

It never gates parsing or analysis. Every transaction always feeds your report's totals and monthly averages, and tally discover always sees everything, regardless of any file's review state. Marking a file reviewed changes only whether its review: true rows appear in the reviews: list above.

The file is hand-editable by design, but PyYAML doesn't preserve comments — anything you add here is lost the next time tally rewrites it (ruamel.yaml, which would preserve them, is deliberately not a dependency). Malformed YAML hard-fails the same way categorization.yaml does: the report is still written, the categorization step reports the parse error, and the file is left untouched.

When a run has review rows waiting, tally up reports it alongside the unknown count:

tally up

Categorization: 36 unknown (0 new, 36 carried forward), 2 awaiting review — confirm to close

See the Formats reference for the full field list, malformed-YAML behavior, and how to turn this off with generate_categorization_file: false.

#Customizing Categories

Tally doesn't have predefined categories. You define them in your rules:

  • Category - Primary grouping (Food, Transportation, Bills)
  • Subcategory - Secondary grouping (Grocery, Rideshare, Utilities)
  • Tags - Labels for filtering (business, reimbursable, recurring)

Tell the AI your preferred structure and it will use it consistently.

#Generating Reports

Once transactions are categorized:

tally up

This generates an HTML report with:

  • Monthly spending breakdown
  • Recurring expense detection
  • Category summaries
  • Transaction search and filtering

#Iterating

As you review the report, you might want changes:

"Move Starbucks from Restaurant to Coffee"
"Split Amazon purchases - anything over $100 should be Shopping > Electronics"
"Tag all transactions in December as holiday"

The AI updates the rules, and you can regenerate the report.
